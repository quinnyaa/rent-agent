### ID оголошення

- З URL: `/inzerat/<ID>/<slug>.php` → regex `/inzerat/(\d+)/`.
- Повний URL: `https://reality.bazos.sk` + href.
- ID стабільний: при оновленні/топуванні оголошення ID не змінюється, змінюється лише дата.

### Пагінація

- Offset у шляху, крок 20: `/prenajmu/byt/`, `/prenajmu/byt/20/`, `/prenajmu/byt/40/`, … з тими ж query-параметрами.
- Загальна кількість: `div.listainzerat .inzeratynadpis` → `Zobrazených 1-20 inzerátov z 152`
  (regex `z (\d+)`).
- Блок `div.strankovani`, посилання «Ďalšia» (наступна) відсутнє на останній сторінці.
- Алгоритм: ходити по offset 0, 20, 40… поки сторінка не порожня і offset < total.
  Запобіжник: максимум 30 сторінок.

### TOP-оголошення і дублі

- TOP позначені `span.ztop`. На стор. 1 їх було 7 (вгорі), далі по 1 TOP на кожній наступній сторінці.
- У знімку 2026-11-03: 152 картки, 152 унікальні ID — TOP-оголошення **не дублюються** у звичайному
  хронологічному місці.
- Але порядок може зсуватися між запитами (нове оголошення під час обходу → картка «переїжджає» на
  наступну сторінку), тому дедуп за ID через `Map` обов'язковий.
- Якщо кількість зібраних унікальних ID сильно менша за `total` → попередження в лог.

### Ціна

- Формат `550 €` (з пробілами / nbsp). Парсимо цифри → `number`.
- У цьому пошуку всі ціни числові, але на bazos бувають `Dohodou`, `V texte`, `Zadarmo` → `price = null`,

### Фото

- Карусель: `div.carousel .carousel-cell img.carousel-cell-image`, URL в атрибуті
  `data-flickity-lazyload` (у першого також `src`). Беремо `data-flickity-lazyload`.
- Схема URL: `https://www.bazos.sk/img/<N>/<останні 3 цифри ID>/<ID>.jpg?t=<timestamp>`
  - `N` = 1, 2, 3… — номер фото;
  - `img/1t/...` — мініатюра 340×213 (у списку);
  - `img/N/...` — повний розмір, перевірено **1200×750** (у HTML вказано 960×600, але файл більший).
- Кількість фото: 3, 6, 13 у досліджених; оголошення може бути й без фото (тоді немає `div.carousel`).
- `?t=` — версія; при зміні фото змінюється → можна використовувати для визначення оновлень.
