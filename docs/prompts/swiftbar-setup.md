# Завдання: індикатор rent-agent у рядку меню macOS (SwiftBar) + автозапуск, увімкнений за замовчуванням

Працюєш у репозиторії `~/rent-agent`. Це локальний агент на Node.js + TypeScript: він шукає оренду квартири на bazos.sk,
аналізує оголошення через `claude -p` і надсилає підхожі в Telegram. Сам агент уже працює, його логіку (`src/`, `prompts/`,
`criteria.md`) **не змінюй**. Твоє завдання — інфраструктура навколо нього:

1. Автозапуск через launchd завжди увімкнений, поки ноут увімкнений: стартує після входу в систему й переживає перезавантаження.
   Його можна вимкнути й увімкнути назад, і вибраний стан теж переживає перезавантаження.
2. Значок у рядку меню (SwiftBar) показує стан агента й дає кнопки керування.

## Що вже є (перевір, перш ніж спиратися)

- `scripts/run.sh` — один прогін для launchd: задає PATH, пише лог у `data/logs/YYYY-MM-DD.log`.
- `scripts/schedule.sh` — керування launchd: `install [хвилин]`, `uninstall`, `status`, `run-now`.
  - Label: `com.rentagent.poprad`
  - plist: `~/Library/LaunchAgents/com.rentagent.poprad.plist` (`StartInterval`, `RunAtLoad=true`)
  - Домен: `gui/$(id -u)`
- npm-скрипти: `schedule:install`, `schedule:uninstall`, `schedule:status`, `schedule:run-now`.
- `data/run.lock` існує, поки йде прогін; у ньому PID процесу. Застарілий lock (процес мертвий) означає, що прогін не йде.
- `data/rent.db` — SQLite (`node:sqlite`; читати можна через `/usr/bin/sqlite3`):
  - `runs(id, started_at, finished_at, seen, new_count, matched, error)`. Час в ISO UTC, наприклад `2026-11-03T10:12:04.344Z`.
    `finished_at IS NULL` означає, що прогін ще йде або впав жорстко. `error` не NULL — були помилки.
  - `listings(source, id, url, title, status, notified_at, …)`. Підхожі мають `status IN ('matched','notified')`.
- `shortlist.md` у корені — надіслані підхожі оголошення.
- `data/logs/launchd.err.log` — stderr launchd.
- Автозапуск зараз **може бути не встановлений**. Перевір через `bash scripts/schedule.sh status`.

## Частина 1. Автозапуск: увімкнений за замовчуванням, перемикач, що переживає перезавантаження

Зараз вимкнути автозапуск можна лише через `uninstall`, а він видаляє plist. Додай у `scripts/schedule.sh` дві команди:

- `disable` — `launchctl bootout gui/$UID/com.rentagent.poprad` + `launchctl disable gui/$UID/com.rentagent.poprad`.
  plist лишається на місці, а стан «вимкнено» launchd пам'ятає між перезавантаженнями.
- `enable` — `launchctl enable …` + `launchctl bootstrap gui/$UID <plist>`. Якщо plist немає, виконай `install`.

Також:
- `install` має робити `launchctl enable` перед `bootstrap`, щоб повторне встановлення завжди вмикало агента.
- `status` має розрізняти три стани: «увімкнено» (завантажено), «вимкнено» (є в `launchctl print-disabled gui/$UID` як disabled)
  і «не встановлено». Друкуй також інтервал, код виходу останнього запуску й кількість запусків.
- Інтервал за замовчуванням — **60 хв** (зараз 30). `RunAtLoad=true` лишається: перший прогін одразу після входу в систему.
- Додай npm-скрипти `schedule:enable` і `schedule:disable`.
- Встанови автозапуск: `bash scripts/schedule.sh install 60`.

## Частина 2. SwiftBar

### Встановлення
- `brew install --cask swiftbar`. Перевір, що Homebrew є (`which brew`).
- Папка плагінів: зроби її окремою, наприклад `~/Library/Application Support/SwiftBar/Plugins`. Не використовуй папку
  репозиторію: SwiftBar запускає **кожен** файл у папці плагінів. У ній має бути **symlink** на плагін із репозиторію.
- Шлях до папки плагінів задай через налаштування SwiftBar (`defaults write <bundle id> PluginDirectory <шлях>`).
  Справжній bundle id візьми з `/Applications/SwiftBar.app/Contents/Info.plist` (`CFBundleIdentifier`), не вгадуй.
- Увімкни для SwiftBar «Launch at login». Якщо через `defaults` чи CLI це надійно не виходить, скажи користувачеві,
  де це ввімкнути в налаштуваннях SwiftBar.
- Якщо якусь команду встановлення чи налаштування системи заблокує дозвіл, не обходь блокування. Дороби решту і в кінці
  дай користувачеві точний список команд, які треба виконати вручну.

### Плагін `scripts/swiftbar/rent-agent.1m.sh`
`1m` у назві означає оновлення раз на хвилину. Bash, без мережевих запитів, має виконуватись **менше ніж за 1 с**.
SwiftBar запускає плагіни з мінімальним оточенням, тому використовуй абсолютні шляхи (`/usr/bin/sqlite3`, `/bin/launchctl`).
Шлях до репозиторію визнач через `readlink` самого скрипта, бо він запускається через symlink, а не захардкодженим рядком.

**Рядок меню** — один значок стану, перевірки в такому порядку:
1. ⏳ — йде прогін: `data/run.lock` існує і PID живий.
2. ⏸ — автозапуск вимкнено або не встановлено.
3. ⚠️ — останній запуск з помилкою: `runs.error` не NULL або ненульовий код виходу в launchd.
4. 🏠 — усе гаразд, агент чекає наступного запуску.

Можна використати SF Symbols (`sfimage=`), якщо виглядатиме краще. Головне — щоб стан читався з першого погляду.

**Випадаюче меню:**
```
rent-agent: увімкнено · кожні 60 хв        (або: вимкнено / не встановлено)
Останній запуск: 14:00 (12 хв тому) · 35 с · ✅      ← місцевий час, тривалість, результат
Наступний: ~15:00
Сьогодні: запусків 5 · нових 3 · підхожих 1
Всього підхожих: 35
Остання помилка: <текст, обрізаний до ~80 символів>   ← лише якщо є
---
▶ Запустити зараз                → bash scripts/schedule.sh run-now   (неактивний, якщо вже йде прогін)
⏸ Вимкнути автозапуск            → bash scripts/schedule.sh disable   (або ▶ Увімкнути → enable)
---
📄 Лог за сьогодні               → open data/logs/YYYY-MM-DD.log
⭐ Shortlist                     → open shortlist.md
📁 Папка проєкту                 → open <repo>
```
- Дії виконуй синтаксисом SwiftBar: `bash=<абсолютний шлях> param1=… terminal=false refresh=true`.
- Час із БД переводь з UTC у місцевий. «Сьогодні» означає з місцевої півночі. Для цього подійде `sqlite3` з `datetime(…, 'localtime')`.
- Якщо БД ще немає або вона порожня, покажи «ще не запускався» замість помилки.

## Перевірка (обов'язково, з реальним виводом)

1. Запусти плагін напряму (`bash scripts/swiftbar/rent-agent.1m.sh`), перевір формат виводу і що він виконується швидше за 1 с (`time`).
2. Пройди цикл: `disable` → `status` показує «вимкнено», плагін показує ⏸ → `enable` → «увімкнено», 🏠.
3. Перевір, що «вимкнено» справді переживе перезавантаження: `launchctl print-disabled gui/$UID` містить label як disabled.
   Після перевірки поверни стан «увімкнено».
4. `run-now`: поки йде прогін, плагін показує ⏳. Після завершення — 🏠 і новий «Останній запуск».
5. `npm test` і `npx tsc --noEmit` проходять. Ти не мав зачепити `src/`, але перевір.

## Документація
Онови розділ «Автозапуск» у `README.md`: `enable`/`disable`, інтервал 60 хв, SwiftBar (встановлення, папка плагінів, що
означають значки). Коротко, у стилі решти README.

## Чого не робити
- Не змінюй `criteria.md`, `prompts/`, логіку в `src/`.
- Не чіпай `.env` і не друкуй його вміст: там токен Telegram.
- Не додавай `ANTHROPIC_API_KEY` нікуди: агент працює лише через підписку Claude.
- Не запускай кілька прогонів паралельно в обхід lock-файла.

## Наприкінці
Коротко повідом: що встановлено, які команди користувач має виконати сам (якщо такі є), як вимкнути й увімкнути агента
(з меню і з терміналу). Додай приклад того, як зараз виглядає меню, тобто реальний вивід плагіна.
